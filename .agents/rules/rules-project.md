# 프로젝트 개발 및 AI 행동 규칙 (Project Development & AI Rules)

## 1. 프로젝트 개요 및 SSOT 원칙
- 본 프로젝트는 향린교회 주보 제작 자동화 시스템(Sunday Bulletin)입니다.
- **영역별 SSOT**: 전체 목적/워크플로우는 `README.md`, 환경/실행은 `docs/setup-guide.md`, 아키텍처는 `docs/architecture.md`에서만 관리합니다.
- 공통 행동 및 보안 규칙은 `.agents/rules/`, 도메인 스킬은 `.agents/skills/`, 워크플로우는 `.agents/workflows/`에 둡니다.

## 2. 크로스 플랫폼 호환성 (Windows & Linux/macOS)
- 실 운영 환경(Windows PC + 한컴오피스)과 개발/배포 환경(Linux/WSL/macOS)을 모두 지원합니다.
- 경로 처리는 `pathlib.Path` 또는 `os.path.join`을 사용하고, 텍스트 입출력은 항상 UTF-8(`encoding='utf-8'`)을 명시합니다.

## 3. 계획 수립 및 변경 전 설명 (Explain Before Act)
- 복잡한 작업이나 파일 수정 전, 현재 상황과 원인을 파악하고 변경 계획을 먼저 사용자에게 브리핑합니다.
- 임의 추측에 의한 과도한 설계를 지양하고 최소한의 외과적 수정(Surgical Changes)을 원칙으로 합니다.

## 4. TDD 및 검증 원칙 (Verification Before Completion)
- 기능 구현 및 수정 시 테스트를 동반하며, 작업 완료 보고 전 반드시 테스트 및 실행 명령을 직접 수행하여 결과(성공 여부, 에러 코드 0)를 확인합니다.

## 5. 커밋 및 Git 관리 규칙
- **선택적 스테이징**: `git add .`를 금지하고, 수정한 파일만 명시적으로 `git add <file>` 합니다.
- **루트 디렉터리 청결**: 임시 파일이나 생성물은 루트가 아닌 `output/` 또는 `tmp/`에 저장합니다.
- **커밋 메시지 항상 한글 작성**: 접두어(`<type>: #<이슈번호>`) 뒤의 설명문은 예외 없이 100% 한글로 작성합니다. (예: `feat: #12 한글 HWPX 템플릿 치환 엔진 추가`)

## 6. 언어 및 소통 정책 (Easy Explanation for Non-Developers)
- 모든 대화와 문서는 한국어를 기본으로 합니다.
- 실제 사용자는 비개발자(교역자, 사무원, 평신도)이므로 난해한 IT 전문 용어를 지양하고, **비전공자도 즉시 이해할 수 있는 쉬운 일상 용어와 직관적인 설명**으로 소통합니다.

- **기본 6개 체계**: `1. 오늘 일정 안내`, `2. 함께 만드는 향린`, `3. 이번주 일정 안내`, `4. 이후 일정 안내`, `5. 에큐메니칼 소식`, `6. 감사헌금`.

- AI는 그 어떤 데이터(본문, 일정 날짜, 모임 주기, 예배위원, 사유)도 자의적으로 지레짐작하여 적지 않습니다.

- `이번주 성서일과`는 교회 홈페이지(`이번주 성서읽기`)에서 다음 주일 게시글을 직접 교차검증하여 구약, 서신서, 복음서 순으로 기입합니다.

## 30. 사용자 수동 편집 사전 자동 감지 및 무손실 계승 원칙 (Auto-detect & Non-destructive Succession)
- 새로운 작업 지시를 받으면, 가장 먼저 `output/` 내 최신 HWPX 파일의 최종 수정 시각을 확인하여 사용자 직접 저장 여부를 감지합니다.
- 사용자가 수정한 흔적이 있으면 이전 원고(YAML)로 덮어쓰지 않고, 수동 편집된 내용(소식 문구, 삽입 그림, 말씀 줄바꿈 서식 등)을 선행 추출하여 시스템 기억에 역반영한 뒤 누적 증분 빌드(`_v{N+1}.hwpx`)를 진행합니다.
