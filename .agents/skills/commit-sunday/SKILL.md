# 주일 주보 전용 커밋 & 푸시 스킬 (`commit-sunday`)

이 스킬은 주보 자동화 프로젝트의 변경 사항을 원격 저장소와 완벽하게 동기화하기 위해 **1) Pull → 2) Clean 상태까지 논리적 분할 커밋 → 3) Push**의 3단계 절차를 자동 수행합니다.

---

## 3단계 실행 절차

### 1단계: 원격 저장소 최신화 (Pull)
- 커밋 작업 전, 먼저 원격 저장소의 최신 커밋을 가져옵니다:
  ```bash
  git pull
  ```
- 원격 변경 사항과 로컬 수정 사이에 충돌이 발생하면 즉시 충돌을 해결한 뒤 다음 단계로 넘어갑니다.

---

### 2단계: Clean 상태가 될 때까지 분할 커밋 (Commit)
1. `git status`로 변경되거나 추가된 전체 파일 목록을 확인합니다.
2. 서로 연관된 파일들끼리 논리적 그룹(예: 엔진/소스, 템플릿/데이터, 문서, 설정)으로 나눕니다.
3. 각 그룹별로 파일명을 명시하여 스테이징합니다 (`git add .` 금지):
   ```bash
   git add <파일1> <파일2>
   git commit -m "<타입>: <설명>"
   ```
4. 모든 파일이 커밋되어 `working tree clean` (커밋할 사항 없음) 상태가 되었는지 확인합니다.

#### 커밋 메시지 규칙 (항상 한글 필수 작성)
```
<타입>: #<이슈번호> <한글 설명>
또는
<타입>: <한글 설명>
```
- **항상 한글 작성 원칙**: 커밋 메시지의 설명 내용은 예외 없이 **항상 한글로만 작성**합니다. 영문 설명은 사용하지 않습니다.
- **타입 목록**:
  - `feat`: 새로운 기능, 엔진, 템플릿 추가
  - `fix`: 버그 수정, 오탈자, 파싱 오류 해결
  - `docs`: README, 가이드 문서, 주석 추가 및 수정
  - `refactor`: 코드 구조 개선, 파일 정리
  - `test`: 단위 테스트 추가 및 보완
  - `chore`: 설정 파일, 패키지 의존성 관리
- **준수의무**: 접두어(`<타입>:`) 및 이슈 번호를 제외한 모든 본문 설명은 100% 한글로 작성해야 합니다.

---

### 3단계: 원격 저장소에 반영 (Push)
- 커밋 내역을 최종 확인한 후 원격 저장소로 푸시합니다:
  ```bash
  git log --oneline -5
  git push
  ```
- 푸시가 성공적으로 완료되었는지 확인하고 최종 보고합니다.
