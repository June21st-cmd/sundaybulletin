# explain-before-act — 작업 전 상황 설명 스킬

AI 에이전트가 무작정 코드를 수정하거나 명령어를 실행하지 않고, 반드시 **현재 상황 파악 → 계획 공유 → 사용자 확인(또는 짧은 브리핑) → 실행** 순서를 따르도록 강제하는 행동 규칙이다.

## 언제 적용하는가
- 새로운 기능 개발, 버그 수정, 리팩토링 요청 시
- 여러 파일에 걸친 변경이 필요할 때
- 작업 범위가 모호하거나 영향 범위가 넓을 때

## 실행 순서
1. **Phase 0 — 침묵 파악 (Silent Research)**: 파일 열람 및 구조 파악 (코드 수정 금지).
2. **Phase 1 — 상황 브리핑 (Situation Briefing)**: 문제 요약, 원인, 영향 범위, 해결 계획을 5줄 이내로 간결히 보고.
3. **Phase 2 — 실행 (Execution)**: 브리핑 후 최소 변경 수행.
4. **Phase 3 — 결과 보고 (Result Report)**: 변경 내용, 테스트/검증 결과, 후속 작업 요약.
