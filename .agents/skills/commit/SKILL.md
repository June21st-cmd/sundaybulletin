# 커밋 스킬 (세션 파일 한정)

현재 세션에서 완료한 작업을 커밋할 때 이 스킬의 제약 사항을 준수합니다. 변경 사항을 작고 논리적인 단위로 묶어 커밋하며, 원격 저장소에 푸시하지 않습니다.

## 규칙

- **테스트 확인 필수**: 로직 파일을 수정했다면, 반드시 관련된 테스트 코드(`tests/`)도 작성/통과되었는지 확인합니다.
- **선택적 커밋**: 이번 세션에서 수정한 파일만 커밋합니다. 전체 작업 트리를 커밋해야 하는 상황이면 `commit-all` 스킬을 활용합니다.
- **논리적 분리**: 관련 변경 사항을 하나의 커밋으로 묶습니다. (기능/수정 단위로 1커밋)
- **`git add .` 금지**: `git add .` 또는 `git add -A` 사용을 금지합니다. 파일명을 명시해서 스테이징합니다. (`git add <파일>`)
- **Push 금지**: 사용자가 명시적으로 요청하지 않는 한 절대 푸시하지 않습니다.

## 커밋 메시지 형식

```
<타입>: <설명>
```

허용 타입: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `style`, `perf`

템플릿:
```
feat: <무엇을 왜 추가했는지>
fix: <무엇이 문제였고 어떻게 고쳤는지>
docs: <무엇을 문서화했는지>
test: <어떤 테스트를 추가/수정했는지>
chore: <어떤 유지보수 작업을 했는지>
```

## 절차

1. `git status` — 수정된 파일 확인
2. 파일을 논리 단위로 묶기
3. 파일 스테이징: `git add <파일1> <파일2>`
4. 커밋: `git commit -m "<타입>: <설명>"`
5. 확인: `git log --oneline -5`
