# 주보 생성 전문가 (bulletin-generator)

매주 바뀌는 주보 원고 데이터(예배 순서, 설교 정보, 찬송가, 교회 소식 등)를 읽어 정형 템플릿에 주입하고, 컬러 인쇄용 HWPX 및 초고속 고화질 Typst PDF를 생성합니다.

## ⚠️ 실행 가드
* **주보 조판(HWP/PDF)은 사용자가 명시적으로 요청("주보 작업해", "HWP 만들어줘")할 때만 실행합니다.**
* 단순 원고 입력이나 텍스트 정리 단계에서는 절대 임의로 생성 명령을 먼저 수행하지 않습니다.

## 표지 사진 및 로고 조판 가이드
1. **대문 사진 및 설명란 조판 규격**:
   - **사진 없을 때**:
     - `image2.png` 파일 삭제 및 `section0.xml` 내 사진 칸(`<cellSz width="52624" height="40060">`)의 `<pic>` 태그 완전 제거.
     - 사진 칸 크기(너비 `52624` × 높이 `40060`)는 절대 수정하지 않고 원형 보존.
     - 사진 설명 칸(`<cellSz width="52624" height="4581">`)은 `╻` 기호 한 줄 문단만 유지 (두 줄 이상 생성 금지).
   - **사진 있을 때**:
     - 원본 사진 파일을 `BinData/image2.png`로 복사하고 `content.hpf` 매니페스트에 등록.
     - 사진 칸(`<cellSz width="52624" height="40060">`)에 골든 레퍼런스 규격의 `<pic>` 태그(`sz width="51000" height="39780"`, `treatAsChar="1"`, `binaryItemIDRef="image2"`) 자동 안착.
     - 4분할 콜라주 등 설명이 2줄일 경우 `headline_left`, `headline_right`를 2개 독립 문단(`paraPrIDRef="37"`, `charPrIDRef="26"`)으로 나누어 기입.
   - **셀 치환 시 고유 규격 필수 매칭 (예배 순서 오염 방지 교훈)**:
     - `rowAddr="5"` 등 일반적인 행 번호로만 매칭하면 예배 순서 표의 5행(여는찬송/교독송 칸)까지 덮어써지므로, 반드시 고유한 셀 크기 규격(사진 칸: `cellSz width="52624" height="40060"`, 설명 칸: `cellSz width="52624" height="4581"`)을 복합 매칭하여 치환.
2. **로고 치환 시 8개 필수 동기화 속성**:
   - `orgSz`: 원본 픽셀 × 75
   - `curSz` & `sz`: 타겟 크기 (촛불 높이 `7,800`, 글씨 높이 `6,200` - 너비는 원본 비율에 맞춰 계산)
   - `rotationInfo`: centerX(target_w / 2), centerY(target_h / 2)
   - `scaMatrix`: e1 = target_w / org_w, e5 = target_h / org_h
   - `imgRect`, `imgClip`, `imgDim`: org_w, org_h에 맞춤
3. **길목 청년활동가 QR코드 표준 규격**:
   - 사용자가 한글 프로그램에서 조정한 최적 규격: `curSz 2321×2321`, `sz 2321×2321`, `horzOffset="49176"`, `centerX/Y="1160"`. 악보(`BinData/image6.bmp`) 보호를 위해 고유 ID `image8` 유지.
4. **예배 순서(2, 3면) 정밀 조판 가이드**:
   - **찬양(성가대)**: 곡명(17pt Bold, `“곡명”`)과 작사·작곡(14pt Regular, ` (글: ..., 곡: ...)`)은 반드시 독립된 2개의 `<hp:run>`으로 분리하여 표기합니다.
   - **성가대 가사 칸**: 기본 높이보다 1mm 축소한 표준 높이(`height="4569"`)를 적용합니다.
   - **교독송(국악시편)**: 3개 연 구조에 맞춰 구절을 분리하며, 마지막 마디 6개 음표 아래 가사는 이음줄 시작 음표(4번째 음표)에 마지막 가사 글자를 맞추고 5~6번째 음표 아래에 각각 `-`를 1:1 대응합니다 (`주  옵소  서  -  -`). 교독송 후렴 악보(`BinData/image6.bmp`)는 절대 덮어쓰거나 삭제하지 않습니다.
   - **하늘뜻펴기 긴 제목**: 우측 빈 칸을 병합(너비 39,958, colSpan 6)하여 확보하고, 17pt 크기 유지, 장평 90%(`ratio="90"`), 자간 0%(`spacing="0"`), 줄간격 125%를 적용하여 우측 침범 없이 칸 전체에 당당하게 1줄로 채웁니다.
   - **함께읽는말씀 본문 칸**: 2면 인쇄 하단 여백 경계선에 밀착되도록 `height="7550"` 수준으로 넉넉히 확장합니다.
5. **공동관심사(소식면) 정밀 조판 가이드**:
   - **소주제 기본 번호 체계**: `1. 오늘 일정 안내`, `2. 함께 만드는 향린`, `3. 이번주 일정 안내`, `4. 이후 일정 안내`, `5. 에큐메니칼 소식`, `6. 감사헌금` (교우 소식이 있을 때는 2번에 삽입되며 번호 순차 밀림).
   - **소주제 간 간격 6pt 규격**: 소주제 사이 빈 문단(`<p>`)은 반드시 **6pt (`height="600"`, `charPrIDRef="125"`, `paraPrIDRef="95"`)**를 적용하여 여백 과다 벌어짐 방지.
   - **이후 일정 안내 항시 유지**: 당장 소스가 없더라도 번호 체계와 서식 틀 보존을 위해 빈 항목(`items: []`)으로라도 섹션 헤더를 항상 유지.
   - **신도회 모임 안내 박스**: 둘째 주일 등 신도회 월례회 주간에는 `신도회 월례회` 항목 바로 밑에 3줄 안내 표(박스) 자동 삽입.
   - **불릿 기호(`∙ `) 자간 0% 원칙**: 글머리 기호는 항상 자간 0%(`charPrIDRef="79"`)의 독립된 런으로 분리하여 전체 들여쓰기 라인 보호.
   - **과부(외톨이 글자) 방지 미세 자간 및 줄바꿈**: 문장 끝에 한두 글자만 떨어져 나가는 현상을 막기 위해 불릿 이후 본문 자간을 -1%~-7% 미세 조절하거나 자연스러운 끊어읽기 위치(예: 향린국악학교 `서도민요반` 뒤)에서 줄바꿈(`<lineBreak/>`) 적용.
   - **소식면 줄간격 규격**: 소주제 헤더 6개는 줄간격 **130%로 불변 고정**하며, 소식 본문은 기본 **170%**를 기준으로 하되 광고가 3페이지로 넘어갈 경우 **5%씩 축소(170% → 165%)**하여 2페이지(5, 6면) 내에 맞춥니다.
   - **사용자 수동 에셋(QR코드/사진) 보존 및 교독송 악보 보호**: 사용자가 주보에 붙여넣은 QR코드/사진(예: `2gtkk.png`)은 교독송 후렴 악보(`BinData/image6.bmp`)와 충돌하지 않도록 독립 ID인 **`image8.png`**로 주입하고 원본 악보를 절대 삭제하지 않습니다.
   - **7면 쪽나눔 및 등록 새교우**: 방문 환영 표 문단에 명시적 쪽나눔(`pageBreak="1"`)을 부여하고, 등록 새교우 발생 시 표 맨 앞(1행 1열)에 추가하며 기존 명단을 뒤로 1칸씩 밀어 4명씩 행을 유지합니다.

## 주보 파일 버전 관리 규칙 (Automatic Versioning)
* **목적**: 사용자가 한글 프로그램으로 주보를 띄워둔 상태에서도 충돌 없이 바로 새 버전을 확인하고 피드백할 수 있도록 합니다.
* **명명 규칙**: `output/[주보] YYYYMMDD_v{N}.hwpx` 및 `.pdf`
  * 첫 생성 시: `_v1`
  * 기존 파일이 있거나 한글 프로그램에서 열려 있을 때: 자동으로 다음 번호(`_v2`, `_v3`...)로 생성.
  * 열려 있는 한글 창을 닫을 필요 없이 새로 생성된 최신 버전을 바로 열어볼 수 있습니다.
* **작업 중간 임시 버전 자동 정리**: AI가 내부 검증/서식 교정 과정에서 여러 버전을 생성한 경우, 사용자에게 완료 보고를 하기 전에 최종 완성본 1개만 남기고 내부 교정용 중간 버전 파일들은 자동으로 삭제·정리합니다.

   - 새로운 주보 생성 또는 수정 작업을 착수하기 전, `output/`의 최신 HWPX 파일의 최종 수정 시각을 확인합니다.
   - 직전 AI 빌드 시점 이후 사용자가 직접 저장한 흔적이 감지되면:
     1. 최신 HWPX 파일의 내부 텍스트, 추가된 행사, 새로 삽입된 에셋(QR코드/이미지)을 추출합니다.
     2. `input/bulletin_YYYYMMDD.yaml` 및 `data/assets/images/`에 해당 변경사항을 즉시 선행 역반영합니다.
     3. 사용자에게 어떤 수동 수정 내용이 감지되어 안전하게 계승되었는지 1줄로 브리핑한 후 다음 작업을 진행합니다.
1. **원고 데이터 준비**: `data/inputs/bulletin_YYYYMMDD.yaml` 작성 또는 AI 정제.
   - 성경 본문 쪽수가 없으면 과거 주보를 대조하여 사용자에게 사전 예상 쪽수를 브리핑하고 확인받아 기입.
2. **생성 명령 실행**:
   ```bash
   python3 src/main.py --data data/inputs/bulletin_YYYYMMDD.yaml --engine all --output output/
   ```
3. **HWPX 필수 무결성 검증 체크리스트**:
   - [ ] **linesegarray 완전 제거**: 치환된 XML에 `linesegarray` 태그가 0개인지 확인 (한글 문서 변조 경고 방지).
   - [ ] **OCF 규격**: zip 아카이브의 Entry 0이 `mimetype`이며 압축 방식이 STORED(0)인지 확인.
   - [ ] **XML 문법 무결성**: `hh:ratio`, `hh:spacing` 등 속성 태그가 self-closing(`/>`)으로 잘 닫혀 있는지 확인.
   - [ ] **로고 8개 속성 동기화**: `sz`, `curSz`, `orgSz`, `rotationInfo`, `scaMatrix`, `imgRect`, `imgClip`, `imgDim` 일괄 동기화 여부 확인.
   - [ ] **소제목 셀 높이 통일**: 징울림부터 함께읽는말씀까지 소제목 행 높이가 `3,217`~`3,218`로 일치하는지 확인.
   - [ ] **찬양 표기 분리**: 곡명(17pt)과 작사작곡(14pt)이 독립된 글자 런으로 분리되었는지 확인.
   - [ ] **교독송 음표 정렬 및 악보 보존**: 음표-가사 1:1 수직 정렬 및 교독송 후렴 원본 악보(`BinData/image6.bmp`) 보존 확인.

   - [ ] **2면 하단 여백 일치**: 함께읽는말씀 칸 밑단이 하단 여백선에 닿도록 확장(`7550`)되었는지 확인.
